# 兩輪共同設計的決策

## 模型與狀態

實際使用本機 Claude Code CLI。
明確指定模型 `claude-opus-5-5`。
兩輪回應的 modelUsage 均回報此模型。
工具存取已停用，只傳送脫敏的需求與質疑。
CLI 沒有取得生產或付款權限。

第一輪建立候選方案。
第二輪由 Codex 質疑，Opus 回應並修正。
此文件是討論結論，不是部署驗證報告。

## 共同採納

- 世界由 Agent 建造，核心只保留原語。
- 首頁也是作品，保底入口為原始目錄。
- 世界從零件作品開始，不放預設寺廟。
- JIC 材料保留來源、版本、授權和內容類別。
- 身份、內容授權、操作能力與付款分開。
- 內容版本不原地覆寫，可分叉及匯出。
- 無權訪問的資料，不因付款而變得可讀。
- LOVE 顯示、USDC 結算，沿用現行 Router。

## 經質疑後修正

| 第一輪提案 | 第二輪修正 |
|---|---|
| 把 JIC JWT 串接列作已有基礎 | 它是目標能力，初稿尚未實作 |
| 放一件種子示範到世界 | 示範只放開發文件，世界保持零件 |
| 同源腳本必然讀核心憑證 | 正確 opaque-origin 與 CSP 可作 v0 隔離 |
| 用 KV 作多人共享狀態 | 強一致序列用 D1 CAS，實時房間後續用 DO |
| payMany 可直接當 USDC 多方結算 | 未確認該 USDC 介面，v0 不聲稱支援 |
| 平台不保存可讀秘密 | runtime 不接收核心秘密 |
| 每項測試都不得使用 mock | 可做單元替身；不可冒充真實整合驗證 |
| 搜尋不到宗教詞就證明架構開放 | 驗收應看第三方能否創造未預設玩法 |
